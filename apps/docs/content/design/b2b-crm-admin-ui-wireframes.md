# B 端客户经营与 CRM 域 — 管理端 UI 线框与导航设计（草案）

**依据**：[数据库表结构设计 — §1 B 端客户经营与 CRM 域](./database-schema-structure.md)  
**范围**：各主表/业务表的**列表、新建、详情、编辑、删除**（删除前**弹窗二次确认**）；表格与表单中字段标签统一为**中文**。  
**状态**：待产品/研发确认后再落地代码。

---

## 1. 全局约定


| 约定项     | 说明                                                                                                        |
| ------- | --------------------------------------------------------------------------------------------------------- |
| 删除      | 列表行操作与详情页均需支持删除；点击后弹出确认框（文案含实体名称或关键字段摘要），确认后提交。                                                           |
| 只读投影    | `account_activity` 为平台**只读投影**，管理端以**列表 + 详情**为主；不提供常规「新建/编辑」；若需纠错，走运营工单或专用「同步/重放」能力（本文档不展开实现）。           |
| 复合主键    | `calendar_workday` 以 `(地区编码, 日历日期)` 为业务主键维度；列表展示两列，编辑/删除以组合定位。                                            |
| 外键展示    | 列表与详情中 `tenant_id`、`user_staff_id` 等外键优先展示**关联实体的中文名称**（如租户经营展示名、员工姓名），并保留跳转详情入口。                         |
| JSON 字段 | `expected_scale`、`observed_scale_summary`、`coupon_config`、`payload` 等以 JSON 查看器或结构化只读块展示；表单中可用折叠区 + 校验提示。 |

## 2. 左侧主菜单（建议结构）

采用**一级分组 + 二级菜单**，避免单级过长。

```
客户经营与 CRM
├── 租户
├── 员工
├── 合同
├── 日历
└── 时间线

```

## 3. 全局页面骨架（线框）

```
┌──────────────────────────────────────────────────────────────────────────┐
│ [Logo] 客户经营 CRM                              [当前用户] [退出]        │
├─────────────┬────────────────────────────────────────────────────────────┤
│             │  面包屑：分组 > 实体 > 当前页                                  │
│  左侧菜单    │  ┌──────────────────────────────────────────────────────┐  │
│  （§2）      │  │ 页面标题                    [主按钮：新建] [刷新]    │  │
│             │  └──────────────────────────────────────────────────────┘  │
│             │  ┌─ 筛选区：关键字 / 状态 / 日期 / 外键选择器 ─────────────┐  │
│             │  └────────────────────────────────────────────────────────┘  │
│             │  ┌─ 数据表格 或 表单 或 详情描述列表 ─────────────────────┐  │
│             │  │                                                       │  │
│             │  │              （各表见 §4）                              │  │
│             │  │                                                       │  │
│             │  └───────────────────────────────────────────────────────┘  │
│             │  [分页]                                                     │
└─────────────┴────────────────────────────────────────────────────────────┘
```

**列表页**典型行操作：`查看` `编辑` `删除`（删除 → 确认弹窗）。  
**详情页**典型操作：`编辑` `删除`（删除 → 确认弹窗）；子表区域可嵌「新建子项」或跳转子表列表并带 `tenant_id` 等查询参数。

## 4. 各主表页面布局与字段（中文标签）

下列「列表列」为建议默认列；表单分「新建/编辑」同一套字段布局即可。

### 4.1 `tenant`（租户）


| 页面    | 布局要点                                                                                      |
| ----- | ----------------------------------------------------------------------------------------- |
| 列表    | 列：租户编码、企业法定名称、经营展示名、租户状态、租户类型、生命周期阶段、测试开始日、测试完成日、转正日、创建时间；筛选：类型、生命周期阶段、状态、关键字（编码/名称）。     |
| 新建/编辑 | 分区：基础信息（编码、法定名、经营展示名、类型、状态）；经营与阶段（生命周期阶段、预期规模 JSON、观测规模摘要 JSON）；关键日期（测试开始/完成、转正日、转正触发摘要）。 |
| 详情    | 只读展示全部字段 + **关联入口**：客户经理分配、测试券、里程碑、合同摘要、充值订单、用量汇总、转正记录、动态、文档、任务（链接或 Tab）。                 |
| 删除    | 弹窗确认；提示将影响子数据或建议先检查分配关系（按实际外键策略文案调整）。                                                     |


**字段中文对照**：租户主键（系统）｜租户编码｜企业法定名称｜经营展示名｜租户状态｜租户类型｜生命周期阶段｜预期规模｜观测规模摘要｜测试开始日｜测试完成日｜转正日｜转正触发类型摘要｜创建时间｜更新时间

## 5. 导航关系（线框 / 流程）

### 5.1 以租户为中心的辐射导航

```text
                    [租户列表]
                         │
           ┌─────────────┼─────────────┬──────────────┐
           ▼             ▼             ▼              ▼
   [租户详情-总览]  [客户经理分配] [测试券列表]   [里程碑列表] …
           │             │             │              │
           │             └─(筛选租户) └─(筛选租户)   └─[里程碑详情]─►[佐证列表/新建佐证]
           │
           ├──► [合同摘要] [充值订单] [用量日汇总] [转正记录]
           │
           └──► [客户动态] [过程文档] [跟进任务]
                      │
                      └──► [动态详情] ──► [评论列表/新建评论]
```

说明：从**租户详情**出发，通过 Tab 或「相关数据」卡片跳转到各子表列表页，并**默认带上 `tenant_id` 筛选**，返回面包屑保持「租户 > 子模块」。

### 5.2 里程碑与佐证

```text
[生命周期里程碑列表] ──► [里程碑详情]
                                │
                                └──► [里程碑佐证：列表 / 新建 / 编辑 / 删除]
```

### 5.3 客户动态与评论、任务

```text
[客户动态列表] ──► [客户动态详情 · 只读]
        │                    │
        │                    └──► [评论：列表嵌套 或 跳转评论管理并带 activity_id]
        │
        └──（可选）► [跟进任务：新建时可选填 source_account_activity_id]
```

### 5.4 主数据与配置

```text
[内部员工] ◄────► [客户经理分配]（员工、租户双向可选入口）
[客户动态类型] ◄──── [客户动态列表]（类型列显示名称，筛选按类型）
[工作日历]（独立配置域，与租户弱关联）
```

### 5.5 标准 CRUD 路由模式（每表一致）

```text
列表页  ──新建──►  新建页  ──保存──► 详情页
  │                    │
  └──编辑──► 编辑页 ───┘
  │
  └──查看──► 详情页 ──编辑──► 编辑页
  │
  └──删除──► [确认弹窗] ──确认──► 列表页（刷新）
```

## 7. 待确认事项（确认后进入开发）

1. **菜单层级**：是否将「用量日汇总」「工作日历」归为仅管理员可见子菜单。
2. `**account_activity`**：是否永久只读；若需「隐藏/标记异常」是否另表扩展而非删改投影。
3. **租户删除**：物理删除 vs 软删 vs 禁止删除 —— 影响列表与删除弹窗文案、接口设计。
4. **权限**：财务相关字段（如充值金额、合同金额摘要）是否在详情分块脱敏。
