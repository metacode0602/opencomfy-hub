## 1. 背景与目标

本应用面向**非技术用户**与**轻度创作者**，将市面上**开放 API 的 ComfyUI 工作流**进行聚合与产品化封装。用户只需按页面提示输入参数（如提示词、风格、时长等）即可生成视频；生成完成后通过**扫码下载**，下载前需**付费**，支持**微信支付**。

**核心目标**
- 将“工作流”抽象为“可售卖的生成模板/产品”
- 降低使用门槛：参数表单化、预设化、可视化
- 保障交付：排队/重试/可观测/对账一致
- 支持商业闭环：计费、微信支付、下载交付、退款与风控

---

## 2. 产品形态与用户角色

### 2.1 端形态
- **H5 Web（首选）**：微信内可直接打开，支付链路最顺滑；PC 也可用
- **管理后台（Web）**：工作流接入、参数配置、定价、订单、对账、风控、运营

> 若后续要做小程序：可复用同一后端与存储；下载交付需适配小程序文件下载限制。

### 2.2 角色
- **游客**：浏览模板、查看示例、生成需登录/绑定手机号（可选）
- **普通用户**：下单、生成、支付、下载、查看历史
- **运营/管理员**：上架模板、配置参数、定价、监控供应商、处理退款与申诉

---

## 3. 核心用户流程（端到端）

### 3.1 浏览与下单
1. 用户进入首页 → 浏览模板列表（分类/热门/新品）
2. 点击模板 → 进入详情页（示例视频、说明、价格、预计耗时、参数说明）
3. 点击“开始生成” → 填写参数表单 → 预估价格/耗时 → 提交生成
4. 创建订单（未支付）→ 跳转微信支付（或微信内唤起支付）

### 3.2 生成与交付
5. 支付成功回调 → 订单变为已支付 → 创建“生成任务”
6. 后端选择可用供应商（某个开放 API 的 ComfyUI 服务）→ 下发任务
7. 前端展示任务进度（排队/运行/失败重试/完成）
8. 任务完成 → 生成“可下载交付物”
9. 用户在“下载页”看到二维码：
   - **PC 端**：扫码在手机打开下载页
   - **手机端**：直接下载/保存到相册（视实现与平台限制）
10. 下载触发交付日志（用于纠纷与风控）

---

## 4. 工作流聚合与“模板化”抽象

### 4.1 模板（Template）定义
将第三方 ComfyUI 工作流封装为平台模板，包含：
- **供应商绑定**：支持多个供应商同一模板（容灾/比价）
- **工作流标识**：workflowId / endpoint / version
- **参数映射**：平台参数 → 供应商 API 参数（类型、范围、默认值、必填）
- **素材输入**：文本、图片、视频、音频（可选）
- **输出定义**：视频格式、分辨率、帧率、时长、码率等
- **计费规则**：按次/按秒/按分辨率/按模型档位/动态价格
- **预估耗时**：用于用户预期管理与排队提示
- **合规说明**：内容政策、版权提示、免责声明

### 4.2 参数系统（关键）
参数必须“表单化”，建议支持：
- **基础字段**：prompt、negative prompt、seed、风格、比例、时长、分辨率
- **高级字段**（可隐藏）：采样步数、CFG、motion strength、参考图权重等
- **字段类型**：string/number/enum/boolean/file/json
- **校验**：范围、正则、互斥/依赖、敏感词检测（可选）
- **预设**：一键填充“电影感/二次元/写实”等组合参数
- **模板版本**：模板更新不影响历史订单可追溯（参数快照）

## 5. 支付与计费设计（微信支付）

### 5.1 支付模式（建议二选一，优先推荐 A）
- **A. 先付费后生成（推荐）**
  - 优点：防止恶意刷算力；成本可控；逻辑简单
  - 缺点：失败需补偿（重试/退款/补发）
- **B. 先生成后付费下载**
  - 优点：转化可能更高（先看成果）
  - 缺点：算力被白嫖风险高；必须做强水印/低清预览/风控

本需求“下载之前需要付费”，但不排除先付费更稳。折中方案：
- **先生成低清带水印预览** → 付费后出高清无水印下载（更复杂）

### 5.2 订单与对账要点
- 订单状态：`created` → `paying` → `paid` → `fulfilled`（可下载）→ `completed`
- 支付状态：`unpaid/paid/refunded/partial_refunded`
- 关键幂等：
  - 微信回调幂等（同一 transactionId 多次回调）
  - 下单与创建任务幂等（避免重复扣费/重复生成）
- 对账：每日对账单、差异处理（人工后台）

### 5.3 价格策略
- **固定价**：简单，适合早期
- **阶梯价**：分辨率/时长越高越贵
- **动态价**：结合供应商成本、排队时间、峰谷（需更成熟）

## 6. 任务编排与供应商接入

### 6.1 供应商（Provider）抽象
对接“开放 API 的 ComfyUI 服务”，统一为内部接口：
- 创建任务：提交 workflow + params + input assets
- 查询进度：队列位置、百分比、阶段
- 获取结果：下载链接/对象存储 key
- 取消任务：超时/用户撤销（可选）
- 回调（可选）：供应商完成后回推

### 6.2 调度与容灾
- **选择策略**：
  - 成功率优先：按历史成功率、平均耗时、错误率
  - 成本优先：按单位价格
  - 负载均衡：按当前排队长度
- **失败处理**：
  - 自动重试：同供应商重试 N 次（网络/偶发）
  - 自动切换：换供应商重跑（需保证工作流兼容/版本一致）
  - 最终失败：自动退款或发放补偿券（策略可配置）

### 6.3 SLA 与超时
- 任务超时：例如 20 分钟（按模板可配置）
- 生成中的可见状态：排队/执行/上传结果/完成
- 用户体验提示：预计等待时间、失败原因可读化

---

## 7. 下载交付与二维码方案

### 7.1 下载交付形态
- 生成结果统一落到**平台对象存储**（推荐）：避免供应商链接失效/带宽不可控
- 生成“下载凭证”：
  - 下载链接带 token（短期有效，如 30 分钟）
  - 或一次性下载码（核销一次失效）

### 7.2 PC 扫码下载（典型链路）
- PC 展示二维码 → 手机扫码打开下载页（同订单/同交付物）
- 下载页校验：已支付、token 有效、未超次数（可选）
- 支持“保存到相册/分享到文件”（根据浏览器与微信限制实现）

### 7.3 下载安全
- 防盗链：签名 URL、Referer 校验（有限）、IP/UA 风控（可选）
- 限制策略（可配置）：
  - 有效期、下载次数、最大并发
  - 异常下载触发二次校验（短信/人机验证，视风险）

## 8. 内容安全与合规（必须预留）

- **内容政策**：涉政、暴恐、色情、侵权等
- **输入检测**：prompt 敏感词库 + 规则引擎（可先轻量）
- **输出抽检**：图片/视频鉴黄鉴暴（成本高，可按需开启）
- **水印策略**（可选）：
  - 未支付预览加水印
  - 付费后去水印
- **用户协议**：生成内容版权、责任归属、禁止用途
- **日志留存**：订单、生成参数快照、交付记录（用于纠纷）

## 10. 数据模型（概念级）

- `User`：用户基础信息、openid/unionid（微信）、手机号（可选）
- `Template`：模板信息、类目、上下架、版本
- `TemplateVersion`：参数 schema、映射规则、计费规则、供应商兼容列表
- `Provider`：供应商配置、健康状态、权重
- `WorkflowBinding`：模板版本 ↔ 供应商 workflow 的绑定关系
- `Order`：订单金额、状态、支付信息、退款信息
- `Payment`：微信交易号、回调原始数据摘要、对账字段
- `GenerationJob`：任务状态、供应商、重试次数、错误码、耗时
- `Asset`：上传素材与产出文件（对象存储 key、hash、大小、时长）
- `Delivery`：交付凭证（token/下载码）、有效期、下载次数
- `AuditLog`：关键操作审计（后台操作、退款、切换供应商等）

## 11. 系统架构（逻辑视图）

### 11.1 模块划分
- **Web/H5 前端**：模板展示、表单、支付引导、任务与下载
- **API 网关/后端服务**：
  - 用户与鉴权（微信 openid）
  - 模板与参数服务
  - 订单与支付服务（微信支付）
  - 任务编排服务（调度/重试/容灾）
  - 交付与下载服务（签名 URL / 下载码）
- **异步队列**：任务下发、状态轮询、回调处理、重试
- **对象存储**：输入素材与输出视频
- **可观测**：日志、指标、告警（成功率/耗时/回调失败）

### 11.2 关键非功能性要求
- **幂等性**：支付回调、任务创建、结果写入
- **安全**：鉴权、签名下载、密钥管理
- **扩展性**：新增供应商/新增模板无需改核心代码（配置驱动）
- **成本控制**：限流、队列、峰谷策略、供应商切换
- **可靠性**：失败可恢复、任务可追踪、对账可解释

## 12. 风险点与应对

- **供应商不稳定/接口变更**：适配层 + 健康检查 + 多供应商冗余 + 模板版本锁定
- **生成失败导致投诉**：自动重试/自动切换/自动退款/补偿券策略
- **支付与任务状态不一致**：以支付回调为准 + 幂等 + 定时补偿任务（补单/补任务）
- **盗链与分享传播**：短期签名链接 + 下载次数限制 + 异常检测
- **内容合规**：输入过滤 + 输出抽检（逐步上线）+ 用户协议与举报通道
- **成本被刷**（如果先生成后付费）：强制预览水印、限频、风控策略

## 13. MVP 范围（建议第一版）

- 模板：3–10 个高转化视频模板（固定价）
- 支付：微信支付（JSAPI/H5），支付后生成
- 任务：单供应商优先 + 简单重试（同供应商）
- 交付：对象存储 + 签名下载链接 + PC 扫码下载
- 后台：模板上架、参数配置、订单/任务查看、手动退款入口
- 合规：基础敏感词过滤 + 免责声明

---

## 14. 里程碑（建议）

- **第 1 周**：确定供应商 API 协议、模板抽象与参数 schema、支付方案选型
- **第 2–3 周**：MVP（下单-支付-生成-下载闭环）+ 基础后台
- **第 4 周**：容灾（重试/切换）、对账、运营能力（模板/定价迭代）
- **第 5 周+**：优惠券、预览水印/高清交付、内容安全增强、多供应商调度
